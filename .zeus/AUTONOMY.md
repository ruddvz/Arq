# ZEUS local autonomy contract

ZEUS is the Arq execution harness. It may adopt reviewed generic harness techniques, but it is never subordinate to a sibling repository or a shared mutable control plane.

## Local authority

ZEUS and the Arq Engineering OS retain local authority for:

- mode, risk, blast-radius and reversibility classification;
- context budgets and routing;
- Arq invariants and source authority;
- evidence states and gate semantics;
- reviewer requirements;
- graph vocabulary and impact interpretation;
- `.arq` persistence/recovery rules;
- merge, deployment and production authority.

A peer harness may suggest a technique. It cannot lower a ZEUS tier, mark evidence verified, waive an invariant, satisfy Engineering OS, or authorize a release.

## Federation boundary

Federation is a reviewed knowledge channel only. It is not a distributed runtime.

ZEUS may study generic graph/extractor techniques, context compilers, coordination state machines, failure modes, benchmarks, test strategies and operator-UX patterns. Local adoption requires provenance, Arq adaptation and validation.

Never automatically import another repository's active claims, locks, project truth, evidence conclusions, risk classification, release authority, secrets or learned project-specific doctrine.

ZEUS must remain fully operable when every peer repository is unavailable.

## ZEUS-specific graph model

A future Arq graph should prioritise relationships such as:

`Rust crate/symbol -> geometry or constraint kernel -> WASM export -> TypeScript binding -> command/tool -> document state -> renderer/UI -> .arq persistence -> benchmark/test -> issue`

Cross-language identity is important, but uncertainty must remain visible. Dynamic dispatch, runtime reflection and AI-inferred relationships are advisory unless a deterministic extractor or controlled declaration proves them.

Do not import LEAPH physical-system entities, CLEO health/product entities or RAAS catalogue/music entities merely because the generic protocol permits extension.

## Context autonomy

ZEUS decides context depth from its existing fast/standard/deep budgets and the task's four-axis classification. A shared context-compiler implementation may be reused only if it respects those local budgets and source-authority rules.

Ordinary Arq work must never need a sibling repository to compile context.

## Operator UX

A future ZEUS status/doctor surface should expose Arq-specific state: mode, tier, blast radius, reversibility, graph freshness, affected packages/languages, evidence state, required gates/reviewers and one next action.

Hard blockers, failed evidence, stale evidence and advisory graph hints must be distinct. A generic green harness status may never hide a failed Engineering OS gate.

## Failure rule

If federation, graph intelligence or an optional adapter fails, fall back to the canonical ZEUS and Engineering OS workflows. Optional intelligence may disappear; invariants, evidence requirements and release authority may not weaken.
