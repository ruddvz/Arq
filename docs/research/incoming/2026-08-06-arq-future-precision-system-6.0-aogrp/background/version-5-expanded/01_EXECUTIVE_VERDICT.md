# Executive verdict

ARQ can become a leading AI-native precision project format, but it cannot reach that position by adding more tables or copying DWG, RVT, STEP, USD, or Onshape. It must make a small set of guarantees stronger and more observable than competing systems.

## The strongest opportunity

`.arq` can unify six concerns that are usually separated:

1. Semantic design intent.
2. Exact and tolerance-aware geometry inputs.
3. Typed operation history and revision identity.
4. Recoverable local-first publication.
5. Truthful interoperability evidence.
6. Permissioned AI proposals with human review.

The file must still keep these layers distinct. A render mesh is not exact geometry. A kernel payload is not semantic authority. A solver result is not professional approval. A successful parser is not lossless interchange. An AI proposal is not an accepted edit.

## Current reality

The public repository describes a real pre-release architecture editor, tested `.arq` libraries, a semantic model, typed operations, a working plan canvas, local journal work, and 3D-related code. It also states that the protected end-to-end workflow and product-reachable project opening are incomplete. The public `STATUS.md` contains an internal 3D contradiction and an unresolved IndexedDB versus SQLite-WASM/OPFS overlap. Current immutable HEAD, working-tree state, open PR identity, and repository ZEUS files were not available through the connected GitHub tool.

Therefore this package is a proposed system and a repository handoff. It is not a release claim.

## Version 5.0 corrections

- Uses August 6, 2026 as the research date.
- Uses MCP 2026-07-28 as the current stable protocol, not 2025-11-25.
- Treats the 2025 protocol as a compatibility target only where clients still require it.
- Records SQLite 3.53.4 as the current upstream release, while package-local Python embeds SQLite 3.46.1.
- Separates official IFC 4.3.2.0 from its later clarification documentation.
- Records OCCT 8.0.0 and OpenUSD 26.05 as current releases.
- Removes Python bytecode and other generated cache files.
- Adds bounded byte preflight and portable sidecar checks.
- Adds a stateless MCP request parser and routing demonstration.
- Adds closure criteria for every unresolved architecture decision.
- Adds a claim ledger that prevents documentation from overstating implementation.

## Recommended first production slice

Do not rewrite the whole file system. At current HEAD, ZEUS should compile the narrow slice that connects existing `.arq` library work to the product:

1. Resolve the accepted working-copy authority between SQLite-WASM/OPFS and Dexie/IndexedDB.
2. Wire bounded file acquisition and preflight to a real project-open worker.
3. Open compatible files into an isolated candidate state.
4. Validate capabilities, migrations, integrity, semantic invariants, and resource limits.
5. Hydrate the workspace only after validation.
6. Publish a portable copy through a separate candidate, fresh reopen, and atomic promotion.
7. Add truthful UI states for editable, preserving read-only, migration required, repair required, unsupported, corrupt, quarantined, and resource-limit exceeded.
8. Add golden fixtures and browser tests on Safari, Chromium, and Firefox.

Only after that slice is verified should ARQ add generalized feature graphs, exact solid kernels, assemblies, domain packs, collaboration, or public AI authoring.
