# Implementation sequence

## Phase 0: Recompile truth

Resolve current HEAD, read repository instructions, run current checks, inventory `.arq` schema and migrations, identify storage overlap, and update `STATUS.md` contradictions.

## Phase 1: Product-reachable opening and publication

Wire existing file acquisition, ARQFS worker, capability preflight, migration candidate, deep validation, workspace hydration, portable save, and reopen verification. This is the highest-value file-system slice.

## Phase 2: Canonical registry and evidence

Formalise schema IDs, operation IDs, capability registry, diagnostic catalogue, evidence records, and compatibility fixtures. Add versioned publication profiles.

## Phase 3: Deterministic cross-language identity

Adopt the encoding ADR, implement Rust and TypeScript encoders, publish test vectors, and prove identical roots. Remove any identity dependency on JSON formatting or SQLite row order.

## Phase 4: Stable feature and selection model

Introduce parameters, constraints, features, selection roles, lineage, ambiguity handling, and regeneration transactions. Prove invalid regeneration leaves the accepted state unchanged.

## Phase 5: Kernel adapter

Select and isolate the exact geometry kernel. Implement recipe inputs, topology lineage outputs, deterministic diagnostics, cancellation, resource budgets, and cache invalidation.

## Phase 6: Assemblies and first non-building demonstrator

Use an adjustable desk or mechanical bracket assembly. Prove parametric change, clearances, drawings, save, reopen, and revision comparison before pursuing a full vehicle.

## Phase 7: Current MCP and Review Centre

Expose read resources and proposal tools using MCP 2026-07-28. Keep application state explicit. Add exact-digest review, MRTR where user input is required, Tasks for bounded long-running analysis, and compatibility tests for selected clients.

## Phase 8: Interchange profiles

Ship one profile at a time. Start with high-value architecture exchange and measured fidelity. Do not market generic “supports IFC” or “supports STEP”.

## Phase 9: Federation and scale

Add pinned child projects, geospatial transforms, partial loading, LOD, derived streaming, and city-scale tests. Keep portable child files independently recoverable.

## Phase 10: Domain expansion

Add product, mechanical, vehicle, aerospace-concept, and urban packs only after the core conformance levels are verified.
