# Project Intelligence Protocol

Zeus must use available Arq project intelligence before creating new assumptions or
parallel systems.

## Sources

### Live repository

Use for implementation state, package boundaries, scripts, schema, tests, issues,
branches, commits and current README/START-HERE.

### Connected project files and library

Use for named blueprints, planning packs, designs, research, audits, exports and prior
artifacts. Search semantically; do not guess from a filename.

### Current conversation and relevant prior project context

Use when the user references previous decisions, visual systems, current work,
repository blockers or generated packs.

### Current public sources

Use for standards, browser/library support, licensing, security, interoperability and
other time-sensitive facts. Prefer primary documentation.

## Arq discovery map

Discover equivalent current paths rather than assuming these exact paths exist:

- README / START-HERE
- current product-engineering blueprint
- `docs/adr/`
- `docs/file-system/`
- model, operations, renderer, storage and performance contracts
- design tokens and icon manifest
- page/component/command catalogues
- backlog and issue dependencies
- quality, benchmark and recovery fixtures
- reference `.arq` files
- implementation overlays and active PRs

## Internal synthesis for M+

- current goal;
- current live implementation;
- current policy/ADR;
- existing systems/assets to reuse;
- unresolved decisions;
- affected packages and devices;
- risks and failure modes;
- binary acceptance;
- verification environment.

## Retrieval discipline

Retrieve the minimum useful context. Prefer current authoritative evidence. Do not
expose private project context unnecessarily. Record contradictions. Do not claim a
source was inspected unless it was.
