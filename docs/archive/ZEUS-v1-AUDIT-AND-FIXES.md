# Zeus v1 Audit and v2 Fixes

## What v1 did well

- Silent-first operation
- Arq-specific invariants
- Bounded verify/fix loops
- Honest write/test status
- Domain routing and untrusted-content handling
- Safe installer and evaluation tooling

## Problems found

1. Too many generic templates could encourage formal but shallow output.
2. Project intelligence was present but not a first-class required protocol.
3. The critique gate was broad but not scored, making “done” subjective.
4. Pixel precision and visual-regression requirements were not comprehensive enough.
5. Existing project contracts/tokens/specs were not strongly required for reuse.
6. Implementation-state and policy truth needed clearer separation.
7. Geometry, file-format and visual quality were not connected through one release gate.
8. External handoff could still over-rely on “read the docs.”
9. Architecture contradictions lacked an automated scan.
10. Visual specifications lacked an automated completeness scan.
11. “Perfect” language could still appear without measurable acceptance.
12. Platform wrappers repeated more policy than necessary.

## v2 corrections

- Lean canonical core
- Project Intelligence Protocol
- Scored 15-lens Senior Quality Gate
- Pixel Precision Protocol
- Architecture and visual-contract linters
- Reuse-first rule
- Evidence ledger
- Explicit Green/Partial/Blocked/Failed status
- Stronger benchmark, migration, accessibility and device evidence
- Fewer duplicated wrapper rules
