# Arq language-system changelog

## 2026-07-27 - Version 4.1

Version 4.1 corrects a deployment-boundary defect found by inspecting the live
GitHub Pages site. The package now treats the public site as a governed consumer
of the language system.

Added:

- hard U+2014 rules for public and product UI copy;
- route coverage across all seventeen public pages and the 404 page;
- static HTML auditing after the marketing build;
- a commit-bound route-hash proof embedded in the deployed artifact;
- post-deploy proof, route-hash and rendered-language verification;
- live-site audit evidence recording 46 U+2014 occurrences; and
- review rules for formulaic negative contrast, self-attestation and broad
  testing assurances.

The release does not infer authorship from a style pattern. It applies the
supplied reference as descriptive editorial input and makes the deployed result
evidence-backed.

## 2026-07-27 - Version 4.0

Version 4.0 adds an editorial-quality contract to the source-hashed language
system. It introduces a public-content inventory, review-required pattern rules,
an evidence and reviewer-role acknowledgement contract, a standalone installed
repository verifier and new generated-context sections for editorial policy and
public-copy coverage.

The package explicitly rejects authorship inference and detector optimisation.
Its editorial checks are prompts for human evidence review.

## 2026-07-27 - Version 3.0

Version 3.0 hardens 2.0 as an evolvable, installable consumer contract.

Added:

- dynamic snapshot validation rather than fixed product counts;
- deterministic source contract and digest with no persisted local path;
- full installation map verification;
- state adapters for live journal/file-flow implementation states;
- public claim-binding and rendered-site test contract;
- conflict resolution criteria, blocked surfaces and expanded drift register;
- semantic message IDs for opening, persistence, permission and AI states;
- support/AI evidence envelopes and response-disposition policy;
- language consumer compatibility versioning; and
- review-required CI audit mode with expiring acknowledgements.

3.0 also records current public-copy reconciliation work for native opening,
local journal semantics, import/export reachability, hardware claims, privacy
transport claims, AI enforcement wording and volatile public counts.

## 2026-07-27 - Version 2.0

Version 2.0 turns the original voice package into a canonical product-language architecture intended to be consumed later by product UI, marketing, documentation, support and product AI.

Added:

- four-layer vocabulary model: engineering, product, support and AI proposal;
- full product ontology for semantic project objects;
- canonical mappings for workspace, save, sync, selection, issue, long-task, AI, file-flow and `.arq` safe-open states;
- explicit state exposure policy: product, diagnostic or internal;
- role/permission language from the current RBAC matrix;
- format and interoperability fidelity vocabulary;
- file/open/migration/recovery language contracts;
- destructive-action, notification, onboarding, search/help, localisation, privacy and telemetry standards;
- support-intent taxonomy and future support-bot contract;
- future product-AI language/authority contract;
- source registry, source precedence and question-specific authority rules;
- `CONFLICTED` fact state and conflict register;
- generated source-hashed repo context design;
- canonical-data validation and state-language coverage validation;
- copy-impact reporting and PR governance;
- language deprecation policy;
- 30-workspace-surface and 57-route-surface coverage snapshot;
- snapshot inventory of 54 tool names, 12 view kinds, six panels and ten workspace state machines.

Important audit finding recorded in 2.0:

- `STATUS.md` contains mutually inconsistent current statements about whether the 3D stack has a live consumer/view surface. The language system marks the fact conflicted rather than allowing downstream copy/support/AI to choose a preferred interpretation.

The package does not change the Arq repository itself. Live integration must refresh source hashes and run the repository gates.
