# What version 4.1 corrects

4.1 is a corrective release of 4.0. It does not rebrand a style review as an
authorship detector. It closes the gap between the language system and the
GitHub Pages site that visitors actually receive.

## Corrected defects

1. Public em dashes were not a hard failure. They now fail source and rendered
   site checks.
2. The 4.0 inventory was incomplete. It listed eight content modules although
   the live route registry has seventeen public pages plus a 404 page.
3. There was no static-output audit. A source change could pass while a template
   or entity encoded U+2014 survived into HTML.
4. There was no deployment identity check. A live scan could approve a stale
   GitHub Pages deployment.
5. Public review patterns did not cover formulaic negative contrasts,
   self-attesting trust language or all-encompassing test assurances.
6. The public source, route map, page registry and built route set were not
   cross-checked as one contract.

## New controls

- `deployed-site-contract.json` defines source, build and live verification.
- `verify-marketing-route-coverage.mjs` reconciles inventory, route map and
  source module metadata.
- `verify-rendered-public-site.mjs` checks generated HTML and writes a
  commit-bound route-hash proof.
- `verify-deployed-public-site.mjs` checks the response set served by GitHub
  Pages against that proof.
- The live audit records the actual 46 U+2014 occurrences and the claim risks
  beside each route.
- A deployment workflow fragment makes the post-deploy check a required result,
  not an optional manual scan.

## Intentional limit

No pattern list can prove whether a person or model wrote copy. The system
enforces evidence, route coverage, specific claims and human review. It does
not score or infer authorship.
